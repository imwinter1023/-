## 2. ★ 最重要的一句话：这是个 Launcher，不是普通 App

`AndroidManifest.xml` 里 `MainActivity` 挂了 `HOME` + `DEFAULT` 的 intent-filter，**它是替代系统桌面的**。
这决定了两件事：

1. **调试时别用 `am start` 直接测**，要真的把它设为默认桌面，才能验证 Home 键行为。
2. **卸载前必须先把默认桌面切回系统桌面**，否则用户会卡在"按 Home 没反应"的状态里。
   给测试同学的验收步骤里一定要写这一条。

还有：`MainActivity` 是 `launchMode="singleTask"` + `stateNotNeeded="true"` + `excludeFromRecents="true"`，
`onBackPressedDispatcher` 里显式吞掉了返回键（桌面没有返回语义）。这些都是 Launcher 的标准配置，别删。

## 3. 六个刻意的技术决策（改动前请先看这里）

### ① 桌面组件的点击**不能**直接拨号

Android 10（API 29）起禁止后台启动 Activity。在 `AppWidgetProvider.onReceive` 里
`startActivity(ACTION_CALL)` 会被系统**静默丢弃**——现象是"点了没反应"，**没有任何报错**，极难查。

所以组件的按钮挂的是 `PendingIntent.getActivity` → `CallTrampolineActivity`（透明、无 UI、`noHistory`、办完立刻 finish）。

另外 `PendingIntent` 的 requestCode 编码是 **`widgetId * 10 + offset`**（拨号 1 / 微信 2）。
这个不能简化成常量：多块组件会互相覆盖，表现成**"点儿子打给了女儿"**。

### ② 全屏来电页必须走「全屏 Intent 通知」

光有 manifest 的 `showWhenLocked` + `turnScreenOn` 不够。从后台把界面推出来，
**只能**靠 `NotificationCompat.setFullScreenIntent()`（见 `IncomingCallActivity.notifyIncoming`）。
老板键式的 `startActivity` 在 Android 10+ 会被吞。

且 Android 14（API 34）起 `USE_FULL_SCREEN_INTENT` 变成**特殊权限**，需引导用户手动开——
`fullScreenIntentSettings()` 已经备好跳转 Intent。

### ③ 全局字号缩放用 `LocalDensity` 覆盖 fontScale

```kotlin
CompositionLocalProvider(LocalDensity provides Density(LocalDensity.current.density, fontScale)) {
    HomeScreen(...)
}
```

只影响 `sp`，子树里所有文字自动等比放大。**不要改成给每个 `fontSize` 手乘系数**——
一定会漏，而且以后新增文字就会漏一处。

七档倍率定义在 `DisplayPrefs.SCALE`（1.00 → 1.95，非等差），设置页通过 `DisplayPrefs.scaleOf(level)` 取，
**倍率数组只允许存在这一份**。

### ④ vector drawable 只有 `<path> / <group> / <clip-path>`

**没有 `<rect>`、`<circle>`、`<line>`**。从设计稿的 SVG 搬图标时必须先转成 path，
否则直接编译失败（报 `expected <path> but got <rect>` 之类）。

### ⑤ RemoteViews 的能力很窄

只支持 LinearLayout / RelativeLayout / FrameLayout / TextView / ImageView / Button 等一撮 View，
**没有 ConstraintLayout**；不能设圆角、不能设自定义字体——圆角只能在布局里用 shape drawable 给
（见 `drawable/bg_widget*.xml`）。

### ⑥ 桌面是长期存活 Activity，刷新靠 `dataVersion` 计数器

`MainActivity` 几乎不会被销毁重建，**`onResume` 时 Compose 不会自动重组**。
所以显示偏好（字号、高对比度、加粗）和家人位数据的刷新，都靠 `dataVersion.intValue++` 触发重读。
新增任何"从别的页面回来要更新桌面"的数据，记得也走这个计数器。

## 4. 我交付前修掉的 8 处缺陷

⚠️ **以下修改没有经过真实编译**（本机没有 Android SDK / Gradle），是按代码阅读发现并修正的。请重点 review 这几处。

| # | 文件 | 原问题 | 不改会怎样 |
|---|---|---|---|
| 1 | `MainActivity` | `POST_NOTIFICATIONS` 只在 Manifest 声明了，**运行时从未申请** | Android 13+ 上来电全屏通知被系统丢掉 → **来电页压根不弹**，且不报错 |
| 2 | `MainActivity` | `READ_PHONE_STATE` 从未申请 | 紧急求助的「第一位没接听自动改拨下一位」安静退化成「只拨第一位」，功能少一半 |
| 3 | `MainActivity` | `onResume` 里没有触发重组 | 用户把字号拉大 → 返回桌面 → **字根本没变**，看起来就是设置没生效 |
| 4 | `MainActivity` | 保存家人号码后没刷新桌面组件 | 组件仍显示旧名字/旧号码，直到重启桌面 |
| 5 | `FontSizeActivity` | 预览用的 `scale` 依赖已保存的 `level`，而 `level` 只在**松手**时更新 | 注释写着"拖动时实时预览"，实际是假的——拖的过程不变，松手才变 |
| 6 | `IncomingCallActivity` | `setShowWhenLocked` / `setTurnScreenOn` 是 **API 27** 方法，但 minSdk 是 26 | Android 8.0 机器上锁屏来电页不显示（且 lint 会报 NewApi） |
| 7 | `DisplayPrefs` | 倍率数组在设置页里被复制了一份硬编码，只靠注释说"保持一致" | 改倍率时只改一处，两处不一致，预览和实际字号对不上 |
| 8 | 多处 | 4 个未使用的 import（含 `by` 委托必需的 `getValue`/`setValue` 之外的两个） | 只是脏，不影响编译 |

修法简述：
- 1、2 在 `onCreate` 里补齐运行时申请（`POST_NOTIFICATIONS` 加了 `TIRAMISU` 版本判断）
- 3 在 `onResume` 里加 `dataVersion.intValue++`
- 4 在 `pickContact` 回调里加 `CallWidgetProvider.refreshAll(this)`
- 5 把滑块状态上提到 `setContent` 层，`scale` / `tag` 改为跟随拖动中的值（`slider.roundToInt()`），**松手才落盘**
- 6 加 `SDK_INT >= O_MR1` 判断，8.0 退回 `FLAG_SHOW_WHEN_LOCKED | FLAG_TURN_SCREEN_ON`
- 7 在 `DisplayPrefs` 暴露 `scaleOf(level)`，设置页改用它，删掉硬编码副本

## 5. 需要你接着做的（按优先级）

### P0 · 来电触发源 —— 不接这条，来电页是死的

现在是 `IncomingCallActivity.notifyIncoming()` **手动调用**，真实来电不会自己弹。
真机上要接系统来电广播：

```kotlin
// API 31+ 用 TelephonyCallback.CallStateListener（SosHelper 里已有可参考的注册写法）
// 低版本退回 TelephonyManager.listen(...) + LISTEN_CALL_STATE
// 收到 CALL_STATE_RINGING → 取出号码 → 反查通讯录是否属于家人位 → notifyIncoming(...)
```

若"来电"指的是**微信视频来电**，则需要走 `NotificationListenerService` 监听微信通知——这条要评估合规与维护成本，建议先明确需求。

### P1 · 首次引导

三个家人位初始是空的。建议做成 3 步向导（一次挑一个人），挑完才算完成设置。

### P1 · 全屏通知权限引导

检测 `NotificationManager.canUseFullScreenIntent()`（API 34+），未授权时引导到 `fullScreenIntentSettings()`。

### P2 · 号码归一化

通讯录取出的号码可能带 `+86`、空格、横线。拼 `tel:` 之前应清洗为纯数字，
否则部分机型 `ACTION_CALL` 会失败或拨错。

### P2 · 机型适配

小米、华为、OPPO、vivo 对「默认桌面」「自启动」「后台限制」的限制各不相同，
必须逐机型实测第 2 节提到的那两条路径。

### P3 · 其他

- 联系人多号码时目前直接取第一个（`readPicked`），产品若要选择，需加二次选择
- 号码目前存 SharedPreferences，正式版按合规要求处理加密/备份
- 桌面组件目前只有拨号 + 微信两个按钮，若要加"视频通话直连"需重新评估（见下）

## 6. ★ 必须如实告知产品的能力边界

**「一键微信视频」在真机上做不到真一键。** 微信没有开放「给指定联系人发起视频通话」的接口——
官方 SDK、开放平台、URL Scheme 都没有。市面上所有号称做到的都是无障碍服务模拟点击：
需要用户开无障碍权限、依赖微信当前界面结构、微信一改版就废、老人极易误触。

本骨架走的是诚实降级：`WeChatHelper.openWeChat()` 只把微信拉起来，
配合微信自带的「聊天置顶」，老人打开后最上面就是家人。**实际是「一键 + 两次轻点」。**

**请不要把时间花在"找接口"上，它不存在。** 也不要未经评估就上无障碍方案。

## 8. 验收清单

装到真机后逐条过。**前两条是人工配置，安卓不允许 App 自己完成**：

- [ ] 设置 → 应用 → 默认应用 → **主屏幕应用** → 选中「夕阳红桌面」
- [ ] 设置 → 应用 → 夕阳红桌面 → **全屏通知** 打开（Android 14+ 才有这一项）

功能项：

- [ ] 按 Home 键回到的是夕阳红桌面，不是系统桌面
- [ ] 进桌面时弹出四个权限申请，全部允许
- [ ] 三个家人位都能从通讯录挑到号码，头像显示姓名首字
- [ ] 点「打电话」**直接拨出，不弹二次确认**
- [ ] 点「微信视频」打开的是微信（预期行为，见第 6 节）
- [ ] 紧急求助点一下开始拨号；第一位不接，约 20 秒后自动改拨下一位
- [ ] **接通后不再继续往后拨**（只认 OFFHOOK，一旦接通就停）
- [ ] 字号设置页拖动滑块，**预览文字跟手实时变**；松手返回桌面，桌面字号也变了
- [ ] 高对比度 / 文字加粗开关，返回桌面后生效
- [ ] 长按桌面添加「夕阳红桌面」组件，弹出"给哪位家人"的选择
- [ ] 点桌面组件的按钮**真的拨出去**（验证跳板 Activity 生效）
- [ ] 摆两块组件分别绑不同家人，分别点击**各自拨对人**（验证 requestCode 编码）
- [ ] 手动调用 `IncomingCallActivity.notifyIncoming(...)` 测试来电页能盖在锁屏上
- [ ] 卸载前先把默认桌面切回系统桌面，确认不会出现"按 Home 没反应"

首次 Sync 最可能报错的三个位置，按概率排：

1. **Compose 编译器与 Kotlin 版本不匹配** —— 已用 `org.jetbrains.kotlin.plugin.compose` 2.0.21 与 Kotlin 对齐，若仍报错，检查三个插件版本是否都是 2.0.21。
2. **material3 `Slider` 的 `steps` 语义** —— 传的是 `LEVEL_COUNT - 2`（steps 是"中间刻度数"，不是总档数）。若档位数量不对，改这里。
3. **lint 的 NewApi 告警** —— API 27 的两处已加版本判断，若还有别的 API 级别问题，按 lint 提示补 `SDK_INT` 判断即可。
